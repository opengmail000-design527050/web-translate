# Web Translate · 网页双语翻译

分段式网页翻译，中英对照。为 X 的长文和科技 / AI 论文调的。

界面沿用 yt-sub-translate 那一套：黑白灰打底，只在关键处点一笔 `#FEBCB9`。
API 设置、配置档、推理三档、连通性测试卡都和它一样，两个插件的设置页可以无缝切换着用。

---

## 装上

1. Chrome 打开 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 「加载已解压的扩展程序」，选中这个文件夹（`C:\Users\001\web-translate`）
4. 点插件图标 → 「设置」→ 填 API Key

第一次安装会自动打开设置页；从旧版本升级不会打扰当前页面。

设置页有两个一键预设，填完 Key 直接点就行：

| 预设 | 地址 | 推理写法 |
|---|---|---|
| `gpt-5.6-luna` | `https://api.openai.com/v1` | `reasoning_effort` 含 `none` |
| `deepseek-v4-flash` | `https://api.deepseek.com/v1` | `enable_thinking` |

模型那一栏是自由输入的：下一代出来了，把字符串改掉就行，别的都不用动。
换了模型 = 换了缓存键，旧译文不会串到新模型头上。

**填完先点「测试连接」。** 那张卡会告诉你三件事：通没通、这次发出去了哪几个推理字段、
模型实际烧了多少推理 token。设成「关闭」却还在烧推理 token，就是推理写法选错了 ——
光看设置是看不出来的，服务商不认你发的字段时会安安静静退回它自己的默认档。

## 用

- **`Alt+A`** 翻译当前页 / 退出翻译
- 或者点插件图标 → 「翻译此页」
- 常看的站（`x.com`、`arxiv.org`…）在设置页「自动翻译的网站」里加一条，以后打开就翻

译文贴在原文正下方，左边一道极淡的竖线。想只看译文，弹窗里切「仅译文」。

默认**只翻正文**：导航、侧栏、按钮、页脚、评论区都不翻。个别页面认不出正文时会自动
退回整页（弹窗里会写明），也可以在弹窗里手动切「整页都翻」。

弹窗里「推理强度」右边写着当前模型，**点它就能在已存的配置档之间切**（每档带着自己的
地址、Key、模型、译文语言、推理写法），不用为了换个模型跑一趟设置页。菜单最后一条
「管理配置…」通向设置页，新建 / 复制 / 重命名 / 删除还是在那边做。换档等于换了模型，
当前页会按新配置重翻一遍（缓存键里带着模型名，各记各的）。

## 省 token

网页翻译最贵的地方不是模型，是「把整页都翻了，而你只读了三段」。四道闸门按拦截率排：

1. **只翻进入视野的段落**。往下滚才翻下一屏，读到哪儿付到哪儿。长文章通常只读三分之一。
2. **同一段文字只翻一次**。导航、页脚、重复卡片在一页里出现十几次，只花一次的钱。
3. **本地缓存按原文哈希存**。刷新、换标签页、明天再来，都是零成本；同一段文字出现在
   别的页面上也直接命中。
4. **明显不用翻的直接扔掉**：已经是中文的、纯数字日期、太短的按钮文字、光秃秃一条网址。

再往下是请求本身：系统提示压到六行，一批凑够约 1600 字符 / 12 段再发（提示词按次收费，
批越大摊得越薄），并发 3 路，推理默认关闭。

这几个数是调好写死的，设置页里不再开放 —— 调它们的收益很小，调错了却会直接抬高错位率
（一批塞越多段，模型越爱把相邻两段并成一句）。设置页只留了「只翻进入视野的段落」这个
真正有取舍的开关，和缓存留多久。

弹窗底部一直显示累计用量，设置页「数据」那一栏更细。

## 正文在哪

默认只翻正文。两层机制：

**一、找正文容器。** 从 `<body>` 往下钻，每层跟着「字最多、且不是一堆链接」的那个孩子走；
内容散在好几个孩子里（一列并排的段落、一串推文）就停在这一层。导航和侧栏永远是正文的
兄弟节点、字数更少，自然被落下。`<main>` `<article>` 只当**下钻的起点**，不当答案 ——
X 的 `<main>` 里同时装着正文列和右边的「你可能感兴趣」，直接认了等于没筛；而时间线上
每条推文都是一个 `<article>`，认了就只翻其中一条。所以还要求它装着页面 40% 以上的文字。

标题常常在正文容器外面、和它平级，所以 `<h1>` 会单独再捞一次。

**二、容器内部再挡一层外壳。** 判据从可靠到不可靠：语义标签（`<nav>` `<aside>` `<button>`
`<dialog>`）→ ARIA 角色（`navigation` `banner` `contentinfo` `complementary` `toolbar`
`button`…）→ 类名关键词。类名那层刻意收得很窄，而且**不含 header / footer 这两个词** ——
文章自己的 `.article-header` 里装的是标题和作者。漏掉几个导航只是小浪费，错杀正文是 bug。

实测：

| | 只翻正文 | 整页都翻 | 排除掉的是 |
|---|---|---|---|
| X 那篇长文 | 82 段 | 125 段 | 左侧导航、Premium 推广、用户名、点赞数、时间戳 |
| 维基 Transformer 条目 | 369 段 / 94k 字符 | 554 段 | 11.6k 字符，全是 Jump to content、Main menu、Random article 之类 |

认不出正文（挑中的容器里一段可翻的都没有）会自动退回整页，弹窗里写明「没认出正文」，
不会让你对着一片没动静的页面发呆。

## 分段翻译是怎么切的

从 `<body>` 往下走，**只钻块级子元素**。行内的东西（链接、加粗、`<span>`…）是段落的
一部分，永远不会自己成段 —— 所以一段带三个链接的正文仍然是完整的一段。

块级还是行内，**由计算样式里的 `display` 说了算，不看标签名**。这条是被 X 逼出来的：
它把正文里的链接包在一个 `display:inline` 的 `<div>` 里 ——

```
DIV[block]  ├ SPAN[inline]  "In the last month, …"
            ├ DIV[inline]   " dynamic workflows"     ← 标签是 DIV，样式是 inline
            └ SPAN[inline]  "."
```

按标签名判断的话 DIV 一律算块级，这一段会被切成「前半截 / 链接 / 句号」三段，
各自送去翻译，读起来支离破碎，token 也白花。反过来，拿 `<span style="display:block">`
当标题的站点也不少，那时候又必须切开 —— 两个方向都只有 `display` 答得对。

`display:none` 的整块跳过（藏起来的文字不花钱）。`display:contents` 按块级处理：
它可能包着好几个真正的块，当成行内会把几段话糊成一段。

切出来大致是这样：

- `<p>Researchers at <a>Google</a> proposed …</p>` → 一段
- `<div><p>甲</p><p>乙</p></div>` → 两段
- `<div>一句话<p>另一段</p></div>` → 「一句话」单独成一段（译文插在它后面），
  `<p>` 照旧是另一段

句子中间被跳过的东西（行内 `<code>`、图标 `<svg>`、我们自己插的译文）既不进原文，
也不会把一句话切成两半。

整棵子树跳过的：`<pre>` `<code>` `<textarea>` `<svg>`、`contenteditable`、
`translate="no"`、`.notranslate`、`aria-hidden="true"`。

开销：维基那篇 Transformer（1.1 万个元素，手头最大的 DOM）整页切一趟 43 毫秒，
`display` 查过就缓存，重扫 28 毫秒 —— 扫描本身有 450 毫秒防抖，够用。

> 0.1.0 在这里栽过两次，都留了回归测试（`test/blocks.test.js`）：
> 一次是往下钻时把**所有**元素子节点都压了栈，行内的 `<a>` `<b>` 各自成了段，
> 而链接之间的纯文本节点根本不是元素、压根没进过栈；
> 一次就是上面 X 那个 `display:inline` 的 `<div>`。

## 对不齐怎么办

一批段落是编好号发出去的（`1|原文`），回来也必须是 `1|译文`。模型偶尔会把相邻两段
并成一句话回来 —— 这时编号整体平移，每一段装的都是下一段的译文，而**光看编号毫无破绽**。

插件的判据是：缺号只要碰到批的首尾任何一端，就整块对半拆开重来，绝不去「补上那一行」。
拆到底还错位，这几段就只显示原文 —— 错位的译文比没有更误导，还会顺着原文哈希毒化缓存。

万一还是撞上了，弹窗里有「译文和原文对不上？重翻本页」，会把这一页的缓存扔掉重来。

设置页「数据」那一栏记着错位的账（翻了几批、错位几批、拆块几次、放弃几段）——
调批次大小或改提示词之后，就靠这一行判断是变好了还是变差了。

## 页面切换、限流和断线

切换模型、目标语言、翻译范围，或者单页应用跳到下一篇文章时，当前页会给所有批次换一代
编号，并让后台真正中止旧请求。旧请求即使晚回来，也不能改新页面、报一条旧错误，或把旧译文
写进新配置的缓存。同一个标签页完整刷新后会换一枚会话编号，不会被上一页的取消状态误伤。

接口返回 429 时，插件优先遵从 `Retry-After`；服务商没给就按 2 / 4 / 8 秒逐级退避。
同一接口的三个并发批次共用冷却时间，不再一起反复撞限流。段落会留在等待状态并自动回来，
最多 5 次才标成失败。后台超过 120 秒没有回应则释放并发名额，弹窗会给手动重试入口。

缓存正文只把本次新增的译文送到后台合并。两个标签页同时看同一页面时，结果取并集；
「重翻本页」的删除也排在同一条队列里，不会刚删完又被迟到的落盘写回来。

单页应用复用一个段落节点、只改里面的文字时，旧译文会被撤掉并按新原文重翻；无限滚动
移出文档的旧段落也会释放，不会一直占着 4000 段的安全上限。

## 跑测试

```
npm test
```

`blocks.test.js` 用一个最小 DOM 跑真的 `content.js`，断言切段的结果（含 X 的推文结构）。
`align.test.js` 用桩跑 `background.js`，断言并段被识破、缺口在中间时只补翻、
反复错位时整块放弃。都不联网。
`popup.test.js` 用一个 DOM 桩跑真的 `popup.js`，断言弹窗里点模型名切配置档这条路：
菜单每档一条 + 「管理配置…」、切换要把整档灌回 settings 且不碰全局设置、
点当前档是空操作（不重复通知页面）、每次打开都重画。

`lifecycle.test.js`、`cache.test.js` 和 `transport.test.js` 专门压竞态：旧请求晚回、DOM 节点复用、
多标签增量写、取消先于请求到达、新旧文档隔离、401 / 500 / 429 的重试分类和真实 abort。

要再跑一层真实浏览器冒烟（网页和 API 都是本地桩，不会消耗 token）：

```
npm install
npx playwright install chromium
npm run e2e
```

## 还没做的

- 混排容器里那截游离行文（上面第三种）只支持双语对照：「仅译文」和「淡化原文」
  是往整个元素上加类实现的，而它只占元素的一截，整个元素一起压会连旁边的块也压掉。
  实测这种单元很少：X 那篇长文的 66 个正文段里只有 1 个。
- **Shadow DOM** 里的内容看不到。
- X 的文章标题抓不到：它是个没有任何语义标记的 `<span>`（`<h1>` 在 X 上是「对话」
  「当前趋势」这类分区标签）。不想为一行字写站点专用代码。
- 悬停原文看单句译文、划词翻译，都还没有。
- 极少数用 `display:flex` 排版的段落，译文可能挤在原文右边而不是下面。
